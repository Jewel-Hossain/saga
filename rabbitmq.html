    AMQP 0-9-1 methods as the broker sees them

      RabbitMQ terms used here

      Exchange
      Receives every publish and decides which queues get a copy. direct matches the routing key exactly, topic matches dotted patterns with * and #, fanout ignores the key.
      (AMQP default) exchange
      The nameless direct exchange "". Every queue is implicitly bound to it under its own name, which is why replies can be published straight to reply_to.
      Binding / binding key
      A rule linking an exchange to a queue. The keys are listed under each queue in the diagram.
      Queue: ready / unacked
      Ready messages wait for a consumer. Unacked ones are delivered but not yet confirmed; the broker keeps them until basic.ack.
      basic.publish · basic.deliver · basic.ack
      Producer sends; broker pushes to a consumer with a delivery_tag; consumer confirms and the broker deletes the message.
      Publisher confirms
      The broker acks the producer once the message is safely in every routed queue. Pair it with an outbox table so the DB write and the publish can't diverge.
      redelivered flag
      Set when a message comes back after its consumer died before acking. Handlers must be idempotent, keyed here by x-idempotency-key.
      basic.nack requeue=false
      The consumer gives up on a message without putting it back, so a poison message cannot loop forever.
      Dead letter exchange (DLX)
      Queue argument x-dead-letter-exchange. Rejected or expired messages are republished there with an x-death header and land in saga.dlq.
      correlation_id · reply_to
      RPC-style properties. The orchestrator puts the saga id in correlation_id and its own queue in reply_to to match replies to sagas.
      Compensating transaction
      The semantic undo for a completed step (refund, release stock, cancel order), run in reverse order when a later step fails.
      Orchestration vs choreography
      One coordinator sending commands and owning the state, or services reacting to each other's events with no single owner.
