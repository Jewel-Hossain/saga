    Terms used here

    Competing consumers
    Several workers consume from one queue; each message goes to exactly one of them. Adding workers adds throughput without changing producers.
    Prefetch (basic.qos)
    How many unacked messages the broker may push to one consumer. With 1, a worker gets a new job only when it finishes the last one, so fast workers take more. With no limit, jobs are dealt round-robin up front and a slow worker hoards its share.
    Priority queue
    Declared with x-max-priority. Ready messages with a higher priority property are delivered first. Messages already delivered (prefetched) aren't reordered.
    Backpressure
    Making a fast producer slow down instead of letting the queue grow without bound. Here x-max-length=8 with overflow=reject-publish makes the broker nack publishes when the queue is full.
    overflow modes
    drop-head (default) silently discards the oldest message, reject-publish nacks the newest one back to the producer, reject-publish-dlx also dead-letters it.
    Throttling · token bucket
    A shared budget of N calls per second. Workers take a token before calling the API and wait when none are left, so the API never sees more than its limit no matter how many workers run.
